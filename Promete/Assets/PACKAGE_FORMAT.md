# アセットパッケージの形式 (1.0)

Assets API (DESIGN_PLAN.md §4.1) のパッケージ形式の仕様。ライターは `Promete.AssetPacker` の `AssetPackageWriter`、リーダーは `Promete.Assets.PackageAssetSource`。定数は `Promete/Assets/Packaging/AssetPackageFormat.cs` にあり、両者が同じソースをリンクしてコンパイルする。

## 全体

```
+----------------------+ 0
| ヘッダ (平文)         |  headerSize バイト (1.0 では 64)
+----------------------+ headerSize
| データ部              |  エントリの中身を並べたもの
+----------------------+ tocOffset
| 目次 (TOC)            |  tocSize バイト
+----------------------+ tocOffset + tocSize
```

- 数値はすべてリトルエンディアンの符号なし整数。
- オフセットは、パッケージの先頭 (ストリームから開くときは、開いた時点のストリームの位置) からのバイト数。パッケージを別のファイルの後ろに連結しても読める。
- ライターは、データ部をヘッダの直後から隙間なく詰め、目次をファイルの末尾に置く。リーダーはこの配置を前提にしない (オフセットと大きさだけを使う)。

## ヘッダ

| オフセット | 大きさ | 名前 | 内容 |
|---|---|---|---|
| 0 | 8 | magic | `50 52 4D 54 50 41 4B 1A` (`"PRMTPAK"` + 0x1A) |
| 8 | 2 | major | 形式のメジャーバージョン。1.0 では 1 |
| 10 | 2 | minor | 形式のマイナーバージョン。1.0 では 0 |
| 12 | 4 | headerSize | ヘッダの大きさ。1.0 では 64。64 未満は不正 |
| 16 | 4 | flags | ヘッダのフラグ (下記) |
| 20 | 4 | (予約) | 0 |
| 24 | 8 | tocOffset | 目次の位置 |
| 32 | 8 | tocSize | 目次の大きさ |
| 40 | 12 | tocNonce | 目次の nonce (Phase 5 の予約)。暗号化しないときは 0 |
| 52 | 12 | (予約) | 0 |

ヘッダのフラグ:

| ビット | 名前 | 意味 |
|---|---|---|
| 0 | TocEncrypted | 目次が暗号化されている (Phase 5 の予約) |
| 1〜31 | | 予約 (0) |

**ヘッダ全体 (0〜headerSize) は常に平文。** Phase 5 で暗号化するのは目次とデータ部だけで、目次の位置と大きさはヘッダから読める (DESIGN_PLAN.md §4.1 の予約)。

## 目次

```
u32 entryCount
entry[entryCount]
(拡張: マイナーバージョンで目次の末尾に足されたもの。リーダーは読み飛ばす)
```

各エントリ:

| 大きさ | 名前 | 内容 |
|---|---|---|
| 2 | pathLength | パスの UTF-8 のバイト数 (最大 65535) |
| pathLength | path | 論理パス (UTF-8、BOM なし) |
| 4 | flags | エントリのフラグ (下記) |
| 8 | offset | データの位置 |
| 8 | storedSize | 格納しているバイト数 (圧縮後) |
| 8 | originalSize | 元のバイト数 (展開後) |
| 12 | nonce | データの nonce (Phase 5 の予約)。暗号化しないときは 0 |
| 2 | extraLength | 拡張領域のバイト数。1.0 では 0 |
| extraLength | extra | 拡張領域 (マイナーバージョンで足すもの)。リーダーは読み飛ばす |

エントリのフラグ:

| ビット | 名前 | 意味 |
|---|---|---|
| 0 | Deflate | データが raw Deflate (RFC 1951、zlib / gzip のヘッダなし) で圧縮されている |
| 1 | Encrypted | データが暗号化されている (Phase 5 の予約) |
| 2〜31 | | 予約 (0) |

- パスは `AssetPath.Normalize` で正規化した形 (`/` 区切り、先頭の `/` なし、`.` / `..` / 空の要素なし、`\` なし、NFC)。大文字・小文字は区別する。重複は不可。
- ライターはエントリをパスの序数順 (`StringComparer.Ordinal`) に並べる。同じ実行環境 (圧縮の実装) では、同じ入力から同じバイト列になる。Deflate の出力は実行環境 (.NET Framework 版の MSBuild と .NET など) で異なりうるので、実行環境が違えば、圧縮したエントリのバイト列は変わりうる。
- 無圧縮のエントリは `storedSize == originalSize`。
- Phase 5 で暗号化と圧縮を併用するときは、圧縮してから暗号化する (`storedSize` は暗号化後の大きさ)。
- nonce (Phase 5) は、パス・エントリのフラグ・暗号化する直前のバイト列 (圧縮したエントリは圧縮後のもの) のハッシュから決める (DESIGN_PLAN.md §5)。元のファイルのバイト列から決めると、実行環境で Deflate の出力が変わったときに、同じ nonce で別の平文を暗号化しうるため。

## バージョンと互換性

- リーダーは、メジャーバージョンが自分と違えば拒否する (`NotSupportedException`)。マイナーバージョンは問わない。
- マイナーバージョンで足してよいのは、古いリーダーが無視しても正しく読めるものだけ: ヘッダの拡張 (`headerSize` を延ばす)、エントリの拡張領域 (`extra`)、目次の末尾への追記。
- フラグに未知のビットが立っていたら、リーダーは拒否する (`NotSupportedException`)。フラグは読み方を変えるものなので、未知のフラグを無視すると誤ったデータを返すため。新しいフラグを使うのは、それを読めるリーダーと同じ Promete から書き出したパッケージだけになる。
- Phase 5 は、予約済みのフラグと nonce を使うので、形式のバージョンを上げない。Phase 5 より前のリーダーは、暗号化したパッケージを `NotSupportedException` で拒否する。

## リーダーの検証

開く時点 (ヘッダと目次) で検証し、壊れていれば `InvalidDataException` にする。メッセージには、ファイルのパスか埋め込みリソースの名前を含める。

- ヘッダより短い (ストリームの位置が末尾より後ろにある場合も含む)、magic が違う、`headerSize < 64`、`headerSize` が全体の長さを超える。
- 目次が範囲外 (`tocOffset < headerSize`、末尾を超える)。目次が途中で切れている、`entryCount` が目次に収まらない。
- パスが UTF-8 として不正、正規化されていない、重複している。
- データが範囲外 (`offset < headerSize`、末尾を超える)。無圧縮で `storedSize != originalSize`。圧縮で `originalSize` が配列の最大長を超える。
- 圧縮で `originalSize > storedSize * 1032 + 64`。Deflate の圧縮率は最大でも約 1032 倍なので、これを超える元のサイズは壊れている (小さな悪意のあるパッケージで巨大なメモリを確保させないため)。

圧縮したデータの破損 (展開に失敗した、展開した大きさが `originalSize` と違う) は、そのエントリを開いた時点で `InvalidDataException` にする。

## 拡張子

ファイル名と拡張子は Phase 4 (MSBuild 統合) で決める (`<AssemblyName>.<Package>.<拡張子>`)。形式は拡張子に依存しない。
